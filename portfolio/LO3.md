## 3. Apply a wide variety of testing techniques and compute coverage and yield

**3.1 Range of techniques.** 140 automated test cases, mostly black-box. *Partition and boundary-value* tests cover the betting rules (minimum bet, minimum raise, short all-in), blind levels and hand categories. Side pots use *category-partition*: cases vary the number of all-in levels, a folded contributor, unmatched chips and an odd chip. The hand is a *finite state machine*, tested for *state* and *transition coverage*. Two *oracles* check calculations: a brute-force evaluator against the fast one on 600 random hands, and exactly enumerated odds against the win-probability estimate. *Statistical* tests compare bot styles over 2,000 identical decisions; *timing* tests check the estimate's speed. System tests run seeded bot-only tournaments with invariant checks and scripted human input. Planned but not done: pairwise testing of bot inputs, property-based tests, mutation testing and MC/DC on the betting conditions.

**3.2 Adequacy criteria.** Each technique has its own. Partition: every class and boundary of a rule has a case. State machine: all seven states, all 11 transitions, and illegal moves rejected. Oracles: no disagreement. Estimate: within 2 percentage points (four standard errors) of the exact value, and 1 s for 2,000 simulations against eight opponents. Structural: *branch coverage* per module, with targets of 80-95% set in the plan. I treat coverage as a gap finder, not proof: executing a line does not mean its result is checked.

**3.3 Results.** All 140 cases pass in about five seconds and no fault was found in the game. Timing is 0.22 s for 2,000 simulations and 1.1 s for 10,000. To test the tests, I put 17 faults into a scratch copy of the game one at a time, such as a raise minimum off by one, a missing ace-low straight and ties counted as wins; 16 were caught. The survivor is unobservable, because a later check raises the same error. Branch coverage: card 97%, betting 92%, evaluator [93%], game [83%], main 81%, pot 77%, bot 56%, probability 42%. Detailed tables are in the supporting results file.

**3.4 Evaluation.** Against the targets, `betting`, `card` and `evaluator` are close, while `pot`, `bot` and `probability` fall short. Most of the shortfall in `bot` and `probability` is code the game never calls (an older bot decision method, and hand-type tables used only for display), so it says more about dead code than weak tests. Real gaps remain: error paths in `pot`, and each betting check refusing a folded or all-in player. Finding no fault is weak evidence, since I wrote both code and tests, so the injected faults matter more: they show the tests can fail. They are few and chosen by me, and mutation testing would measure this properly.
